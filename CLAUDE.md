# House Project

Personal design app for a 1,000+ acre private estate plus a forestry and wildland fire compound. React, Vite, TypeScript, Three.js. Spec: https://claude.ai/artifact/GwgQKAxxUeUKHBpy1vnjp7

```bash
npm install
npm run dev     # Vite on http://127.0.0.1:5173 plus the local chat server on 127.0.0.1:8787
npm run stop    # stop anything left on ports 8787 or 5173, e.g. after a crashed dev run
npm test        # Vitest (model, history, server loop with a fake Claude, key isolation)
npm run build   # type-check src and server, vite build, then scan dist/ for credentials
```

## Rules

1. **Never deploy.** No Vercel, Railway, Supabase, or any other deploy, publish, or hosted-environment change unless Garrett explicitly says to in that conversation. A previous approval does not carry over.
2. **Work on a branch.** Never commit to `main` or push to `main` unless Garrett says so. Create or use a feature branch for every change.
3. **Geometry lives only in the shared model.** `src/model` is the single source of truth, and every stored length is in inches. `src/views` only draws that model: views must not hold their own copy of positions, sizes, or extents, and must not change the model. Derive anything a view needs from the model, and add it to `src/model` if it is missing.
4. **Passing checks is not code compliance.** `src/model/validate.ts` holds planning checks. In UI text, commit messages, docs, and replies, describe results as "passed this app's checks" or similar. Never say or imply a design is code compliant, permit ready, or safe to build from.

## Layout

- `src/model/types.ts`: model types. Site coordinates are x east, y north, origin at the southwest parcel corner.
- `src/model/geometry.ts`: `ft()` and `toFt()` convert feet and inches; rectangle helpers.
- `src/model/sampleEstate.ts`: the approved sample layout. `src/model/house.ts`: placeholder main house massing, with room coordinates local to `house.origin`.
- `src/model/validate.ts`: planning checks, returning `pass`, `warn`, or `fail`.
- `src/model/derive.ts`: geometry computed from other model data. The main house building's outline comes from its rooms and `house.origin`; never edit it by hand. `parts` are above-grade masses (drawn and extruded); `footprint` adds rooms on levels below elevation 0 and is what collisions use.
- Checks list the ids they are about in `elements` when they do not pass; the plans outline failures in red and warnings in amber.
- `src/model/walls.ts`: walls are derived from room rectangles (room edges are wall centerlines), never stored. Exterior, interior, and foundation thicknesses live in `house.wallThickness`. Below-grade levels list their `exposed` sides (the walkout is exposed to the south).
- Openings (`house.openings`) are stored on a host room's side with an `offset` from that side's west or south end to the center. What they lead to is derived. `applyOperations` rejects edits that leave a previously fitting door or window off its wall.
- `src/model/firstPass.ts`: the rule-based first pass of doors, windows, and stairs. A placeholder to edit, not a design. Saved projects without openings get it on load.
- `src/model/wallChecks.ts`: openings fit, reachability, circulation, exit door, door sizes, hall widths, escape windows, stairs, and wall stacking. Values come from the 2006 IRC as planning values only; the detail text says so.
- `src/model/edits.ts`: named edit operations (`moveBuilding`, `resizeBuilding`, `moveRoom`, `resizeRoom`, `addRoom`, `removeRoom`, `renameRoom`, `setRoomType`). `applyOperations(estate, ops)` is pure, all or nothing, and rejects unknown ids, invalid sizes, and any new overlap between rooms on a level or buildings on the site. All chat and future manual edits go through it.
- `src/model/editTools.ts`: the tool definitions Claude sees (in feet) and the converter to edit operations (in inches).
- `src/model/history.ts`: revisions, undo and redo, saved-project format.
- `src/storage/projectStore.ts`: `ProjectStore` interface for the project and the chat transcript; the browser (localStorage) implementation is used today. Replace it with a Supabase store later without touching callers.
- `src/model/fireChecks.ts`: wildfire and fire-access advisories (defensible space, ignition resistance, road width, dead-end turnarounds, two ways out, hose pull to roads or hardstand, fire water). Values live in `estate.fireRules` (defaults in `DEFAULT_FIRE_RULES`) so Garrett's own standards can replace them. Roads carry `width` and `turnaround`; zones can be `hardstand`; buildings carry `ignition`; `estate.waterSources` holds cisterns and dry hydrants. These are always warnings, never failures.
- `src/model/utilities.ts` and `utilityChecks.ts`: utilities (`estate.utilities`: well, storage, septic, service, solar, generator, propane) sit on site rectangles that count as cleared ground, carry a `capacity` in their kind's unit, and list the buildings they `serve`. Utilities that serve any of the same buildings form one system. Buildings carry `beds`, `staff`, `backupPower`, `fuelStorage`, and an optional `loadKw`; the main house counts two beds per bedroom. Demand for water, sewage, and power comes from those. Checks cover coverage, well and storage supply, septic and drainfield size, grid and generator capacity, separation distances (wells, drainfields, propane by tank size), sun on solar arrays, sewer, generator, and propane run lengths, and parking. Values live in `estate.utilityRules` (defaults in `DEFAULT_UTILITY_RULES`). Always warnings, never failures. `applyOperations` rejects utilities on buildings or on each other.
- `src/model/securityChecks.ts`: cameras and lights (`estate.security`). Cameras have a facing, field of view, and range, and cannot see through more than `cameraForestFt` of uncleared forest (`openGround`, a 20 ft grid). Devices `on` a building move with it. Checks cover gates, the approach inside each gate, building coverage, lighting (the private estate stays dark on purpose), backup power for cameras and gates, and the main house safe room (a room with `safeRoom`: no windows, no door outside, no framed outside walls). Always warnings.
- `src/model/terrain.ts` and `terrainChecks.ts`: existing ground from the parcel's generated terrain (`groundAt`, `roadGrade`, `siteSlope`, `contours`). A house's main floor sits at existing ground in the middle of its footprint (`houseDatum`); `existingGrade` is ground relative to that. Checks: road grade, building-site slope, walkouts against the fall of the land, septic draining downhill unless the utility is `pumped`, drainfield slope and wells above nearby drainfields, and buildings in hollows unless they have a `swale`. Rule values are in `utilityRules`. Always warnings. Elevations and sections draw existing grade dashed; the site plan's Terrain layer and AS-101 draw 10 ft contours. The designed grade is `src/model/designGrade.ts` (`gradeAt`); a house with `excavated` is dug to it, and `earthwork` estimates the cut and fill.
- `src/model/beams.ts`: beams (`house.beams`) carry upper walls over open floor. Each runs along a line in house-local inches under the level whose walls it carries, from wall to wall below, with optional `posts`. The first pass (`firstPassBeams`, run by `withHouseDefaults` for houses without beams, and by the `fitBeams` edit) breaks beams over walls they cross and adds a mid-span post over rooms that can take a column. Sizes are planning estimates from the span (`beamSize`). The stacking check counts beams as support; `beamChecks` warns about ends with no wall and spans over `maxBeamSpanFt`. Plans show beams dashed as "above" on the level below; A-602 is the beam schedule.
- `src/model/furniture.ts`: a catalog of furniture, fixtures, appliances, and machines at real sizes (with parts for drawing, walking room, seats, and kW), and `house.furniture` placing them by center and facing. `firstPassFurniture` furnishes each room from a recipe by room id, name, or type: wall pieces go back to a wall, center pieces near the middle, floor pieces hug the walls, all inside the room, off each other's walking room, and clear of doors. Houses that adjust openings after `withHouseDefaults` furnish again afterward. `furnitureChecks` (per house) warns about pieces that overlap or leave their room, crowded walking room or blocked doors, and rooms short of the seats the program asks for (`ProgramItem.seats`). Plans draw pieces (Furniture toggle, draggable), sheets draw thin outlines, House 3D draws blocks. Edits: addFurniture, moveFurniture, rotateFurniture, removeFurniture, furnishRoom; furniture moves and goes with its room.
- `src/model/shops.ts`: the compound's shops are detailed buildings in `estate.houses`, generated from what they hold (`SHOP_SPECS`): Garrett plans at least 25 of every machine, everything indoors, with a realistic contractor head count (only a few crew carriers). Machines park nose to tail in drive-through lanes with an overhead door at each end; support rooms (gear lockers, hose wash, fitness, ready room, offices, parts, welding) sit in a west wing. `ProgramItem.holds` sets the fleet each bay room must hold, checked by the `fleet` check. Drawings pick a smaller scale for long buildings (`scaleFor`); the chat summary collapses rows of overhead doors and machines. Site plan labels are placed so they never overlap (`placeLabels`).
- `src/model/amenities.ts`: three more detailed buildings from Garrett's answers on 2026-11-09. The office and dispatch building (one story, lodge-style, at the compound entrance: reception, 50-seat training room, 16-seat conference room, 8-position dispatch floor beside a 40-seat emergency operations room, radio and server room, Garrett's executive suite with bath, private conference, lounge and bar, and its own entrance, open office for about 24, six private offices, break room, records, mail and supply, showers and lockers). The car collection building (20-car two-story showroom, 35-car storage hall, toys, wash, detail, body and prep, paint booth and mixing, 4 lifts, tire and alignment, parts, and a mezzanine lounge, bar, and event space). The entertainment shop (35,000 sq ft indoor kart track opening onto the outdoor track, kart pit, trampoline park with foam pit, climbing wall, laser tag, sports court, 4-lane bowling, arcade, two golf simulators, gaming lounge, snack bar, party room, viewing mezzanine). The car building and entertainment shop sit beside the outdoor kart track off their own drive, linked by a covered walkway; staff reach events through the estate gate.
- `src/model/wings.ts`: wings (`house.wings`) let a house bend. Each is a frame turned `angle` degrees counterclockwise about a house-local `pivot`; rooms, roofs, and beams with a `wingId` keep plain rectangles in that frame, so walls, doors, furniture, and checks work unchanged inside it. Walls only join rooms in the same frame; at a joint, an opening on each side names the room beyond (`Opening.through`). Pivot a wing at the inside corner of its turn so it swings clear; `house-rooms` fails rooms in different frames that share more than `JOINT_WEDGE_SQFT`. Outlines use the box around a turned room. Plans, sheets, DXF, elevations, the roof plan, 3D, and the walkthrough turn wings into place; sections leave them off for now.
- `src/model/ceilings.ts`: room ceilings (`Room.ceiling`): flat (the default, just under the floor above), vaulted (two planes from the plate on the long walls to a peak, with king-post timber trusses at `spacing` and a ridge beam), beamed (flat with exposed beams), or tray. `ceilingPolygons` and `ceilingTimber` give the shapes in the room's frame; House 3D draws them seen from inside only, sections cut the vault profile, plan sheets note the form. `ceilingChecks` warns about living spaces under 7 ft and vaults or trays with rooms built above or peaks within 12 in of the roof (`roofHeightAt`). Edit: setCeiling.
- `src/model/bays.ts`: a window with `bay` projects out of its outside wall, box or angled (45 degree sides), 1 to 4 ft, optionally with a window seat. Plans, sheets, and 3D draw the projection; `bayChecks` warns about bays on inside walls, too narrow or deep, or projecting into another room. Edit: setBay. Wide windows draw as glass panels with dark mullions; a vault's `glassEnds` glaze its end triangles.
- `src/model/materials.ts`: per-building palettes (`house.style`: mountain-modern, metal-timber, lodge, glass-gallery) from the brief. House 3D colors siding, stone base, roof, frames, glass, interior, ceilings, timber, and floors from them; catalog pieces with `material` (stone fireplaces, timber built-ins) take the palette's stone or timber. Edit: setStyle.
- `src/model/roofs.ts`: roofs are stored (`house.roofs`) as a covered rectangle, the level whose walls they sit on, form (gable, hip, shed), pitch, ridge direction or low side, and overhang. `roofPolygons` turns each into 3D planes and gable walls; elevations, the roof plan, and House 3D all project those same polygons. Rooms marked `twoStory` rise through the floor above. Building height on the site comes from the roofs.
- `src/drawings`: draft drawing sheets derived from the model as simple marks in sheet points: G-001 cover and index, AS-101 site plan at 1" = 300'-0" keyed to building and utility schedules (cameras and lights left off on purpose), A-101+ floor plans at 1/8" = 1'-0" on ARCH D, A-201 and A-202 elevations (grade assumed, falling south), A-301 roof plan, A-401 building sections (cuts chosen by `sectionCuts.ts` and marked on every plan), A-601 door and window schedules, A-602 beam schedule. `dxf.ts` writes the floor plans as an ASCII DXF in inches, one layer set per level, built in the browser. Marks (D01, W01) come from `marks.ts`. The same marks render to SVG in the Drawings view and to PDF on the server (`server/pdf.ts`, POST /api/sheets.pdf). Every sheet carries the draft, not-for-construction stamp.
- `src/views`: SVG site and house plans, Three.js scenes. House 3D has a Fast / Detailed switch (remembered per browser): Detailed (`src/views/look3d.ts`) uses physically based materials with procedural textures at real scale (timber siding, dry-stack stone, standing seam, plank floors, tile, grass) from the building's palette, sun shadows, filmic tone mapping, soft reflections, and shaped furniture (beds, sofas, tables on legs, counters with stone tops, vehicles with wheels, fireplaces with fireboxes); Fast draws flat blocks.
- `src/ui`, `src/App.tsx`: chat panel, proposal preview, checks, history.
- Tours: `src/ui/tour.ts` holds the flyover keyframes (from the drive, house, compound, and airstrip) and walkthrough collision (walls block, doors and cased openings pass). Scene3D only animates them.
- Drag to edit: `src/ui/dragOps.ts` turns a drag into one named edit (moveRoom, moveWall, moveOpening, moveBuilding, moveUtility, moveDevice), snapped to 6 in, 3 in, or 1 ft. Views only report the edit; App applies it through `applyOperations`, previews while dragging, and commits it as an owner revision on drop. Checks run on drop, not every frame.
- `server/`: local Express server. Calls Claude (model from `HOUSE_MODEL`, default `claude-sonnet-5-5`), dry-runs the proposed edits, returns them. It never saves anything.

## Other notes

- `docs/design-brief.md` records Garrett's design decisions for every building. Read it before changing a building, and add to it when he decides something new.

- Detailed buildings: the main house is `estate.house`; others with their own rooms live in `estate.houses` (today the guest house, `src/model/guestHouse.ts`, a v1 layout for big gatherings). Room, opening, roof, and level ids are unique across all of them. `src/model/houses.ts` has `allHouses`, `focusHouse` (swaps a building into the `house` slot so views, drawings, and checks written for one house work on any), and `checksForEachHouse` (runs house checks per building and merges them by id, details labeled by building). `applyOperations` routes room, opening, and roof edits to the building that owns the id; `addRoom` goes by level id. Old saves get the guest house layout where its box stood (`withGuestHouseDefaults`).
- The main house is the third layout (v3), still a concept, from Garrett's 2026-11-09 brief: a mountain modern courtyard U, about 25,800 sq ft. The center bar holds the kitchen, dining, bar, the vaulted great room with a glass gable (the indoor pool under it), and a lower hearth room on the courtyard side, with the garage, library, stair, tall entry, den, and gear room on the north. The west wing (guests below, kids above, joined to the kids' rooms over the bar's west end) and the east wing (the primary suite) turn 20 degrees off the bar's outside corners. The courtyard is dug to the walkout floor, with the covered porch above it and the outdoor pool at its open south end. Garrett found v1 too compound-like and v2 boxy. Its bearing lines and design intent are at the top of `src/model/house.ts`; keep new walls on them where possible so floors stack. A saved browser project with no edits of its own follows the current sample (`resumeProject`).
- `house.program` holds the brief as checkable requirements (`src/model/programChecks.ts`): rooms, levels, minimum areas and widths, and rooms that must share a wall. Update it when Garrett changes the brief.
- API keys stay on the server. The Anthropic key lives in `server/.env` (git-ignored; see `server/.env.example`). Nothing under `src/` may import `@anthropic-ai/sdk`, read a key, or import from `server/`; `src/keyIsolation.test.ts` and `scripts/check-bundle.mjs` enforce this. Vite is configured to refuse serving `server/` and `.env` files.
- Chat edits are proposals: the browser previews them, shows check changes, and commits only when the owner clicks Apply. Edits that make checks fail can still be applied, flagged in red. Overlaps are the exception: they are rejected before they become a proposal, and Claude must fix or explain them.
- Everything is local only for now. The chat server binds to 127.0.0.1 and rejects requests from other origins.
